¿Qué es y para qué sirve?

El conector Gmail Workspace permite que el agente de Ruvic lea, busque y envíe correos desde uno o varios buzones de tu dominio Google Workspace, usando una sola credencial administrada centralizadamente por tu equipo de TI — sin que cada usuario tenga que autorizar su propio buzón por separado. Ideal para automatizar buzones compartidos de un equipo. Una vez configurado, puedes pedirle al agente cosas como:

  • "Revisa el buzón de facturación y resume los correos nuevos."
  • "Busca en soporte@empresa.com los correos de la última semana sobre 'incidente crítico'."
  • "Envía desde cobranzas@empresa.com un recordatorio de pago con el estado de cuenta adjunto."

Operaciones soportadas:

Operación Qué hace
mail.list Busca/lista correos usando filtros (sintaxis de búsqueda de Gmail)
mail.read Lee el detalle y el cuerpo de un correo
mail.send Envía un correo de texto
mail.send_with_attachment Envía un correo con un archivo adjunto (máx. 20 MB)
Solo para Google Workspace Este conector usa delegación de dominio, una función exclusiva de Google Workspace. No funciona con cuentas de Gmail personales (@gmail.com) — para esas usa el conector "Gmail" (OAuth2) o "Gmail (IMAP/SMTP)".

Prerrequisitos

  • Una organización con Google Workspace (no funciona con cuentas de Gmail personales @gmail.com).
  • Acceso de superadministrador de Google Workspace — es la única persona que puede autorizar la delegación de dominio (paso único, sección 3).
  • Acceso al Google Cloud Console del mismo dominio, con permisos para crear un proyecto y una cuenta de servicio.
  • Los correos de los buzones que el agente va a usar (ej. facturacion@tuempresa.com).

Configuración en el fabricante

Vas a crear una cuenta de servicio en Google Cloud y autorizarla mediante delegación de dominio para que pueda actuar en nombre de cualquier buzón autorizado. Esto se hace una sola vez por dominio — después, agregar un buzón nuevo no requiere repetir estos pasos, solo compartírselo al agente por su correo.

  1. Crea (o selecciona) un proyecto en Google Cloud Console.

    Ve a console.cloud.google.com/projectcreate y crea un proyecto (o reutiliza uno existente del mismo dominio).

  2. Habilita la Gmail API.

    En el menú APIs y servicios → Biblioteca, busca "Gmail API" y pulsa Habilitar.

  3. Crea la cuenta de servicio.

    En IAM y administración → Cuentas de servicio → Crear cuenta de servicio. Dale un nombre (ej. ruvic-gmail-workspace) y termina el asistente sin asignar roles adicionales de proyecto.

  4. Genera y descarga la clave JSON.

    Abre la cuenta de servicio creada → pestaña Claves → Agregar clave → Crear clave nueva → JSON. Se descargará un archivo .json: guárdalo, lo usarás en el formulario de Ruvic.

    [ Captura: pestaña Claves de la cuenta de servicio con el botón "Agregar clave" — reemplazar por assets/img/workspace-sa-key.png ]
  5. Anota el ID de cliente único de la cuenta de servicio.

    En la pestaña Detalles de la cuenta de servicio, copia el ID de cliente único (una cadena numérica larga). Lo necesitarás en el siguiente paso.

  6. El superadministrador autoriza la delegación de dominio (paso crítico).

    Este paso solo lo puede hacer el superadministrador de tu organización de Google Workspace — no un usuario normal ni un administrador de solo Cloud. Ve a admin.google.com → Seguridad → Control de acceso a las API → Delegación en todo el dominio. Pulsa Agregar nuevo e ingresa:

    • ID de cliente: el ID de cliente único copiado en el paso anterior.
    • Alcances OAuth (exactamente estos dos, separados por coma, sin espacios extra): 
      https://www.googleapis.com/auth/gmail.readonly,https://www.googleapis.com/auth/gmail.send

    Guarda. Sin este paso, cualquier intento de conexión falla con el error unauthorized_client.

    [ Captura: pantalla de delegación en todo el dominio con el ID de cliente y los scopes — reemplazar por assets/img/workspace-domain-delegation.png ]
  7. Define qué buzón usarás para la prueba inicial.

    Anota el correo de un buzón del dominio (ej. facturacion@tuempresa.com) para el formulario de Ruvic. Después de configurado, el agente podrá usar cualquier otro buzón autorizado del mismo dominio, no solo este.

Permisos requeridos

Principio de mínimo privilegio: la cuenta de servicio solo necesita estos dos scopes de Gmail. No autorices scopes de administración, de Drive ni de otras APIs de Workspace.

Scope Para qué lo usa el conector
gmail.readonly Buscar y listar correos (mail.list), leer el detalle de un correo (mail.read)
gmail.send Enviar correos (mail.send, mail.send_with_attachment)
La delegación aplica a TODO el dominio A diferencia de OAuth2 por usuario, estos scopes no se limitan a un buzón — la cuenta de servicio puede impersonar cualquier buzón del dominio con esos permisos, incluidos los que se creen en el futuro. No hay forma de restringirlo a una lista específica de buzones desde el Admin Console.

Configuración en Ruvic

Entra a Settings → Conectores, busca la tarjeta Gmail (Google Workspace — cuenta de servicio) y pulsa Configurar. Diligencia el formulario con los valores que obtuviste en la sección anterior:

Campo del formulario Valor
JSON de la cuenta de servicio Abre el archivo .json descargado en el paso 4 y pega todo su contenido
Buzón de prueba El correo definido en el paso 7 (ej. facturacion@tuempresa.com)
Timeout de solicitud Opcional; 30 segundos por defecto

Guarda y pulsa Probar conexión — la plataforma se conectará a Gmail API impersonando el buzón de prueba y confirmará que la delegación de dominio funciona.

[ Captura: formulario del conector Gmail Workspace en Settings → Conectores — reemplazar por assets/img/workspace-form.png ]

Verificación

  1. Test de conexión exitoso.

    El botón Probar conexión debe responder: "Conexión exitosa al buzón facturacion@tuempresa.com (delegación de dominio)". La tarjeta del conector cambia a estado Configurado.

  2. Automatización mínima de prueba, incluido un segundo buzón.

    Abre una conversación nueva con el agente y pídele:

    "Busca en el buzón facturacion@tuempresa.com los correos no leídos de los últimos 3 días."

    Luego prueba con otro buzón del dominio distinto al de la prueba inicial (ej. soporte@tuempresa.com) — si el agente responde con datos reales de ambos sin pedir nueva configuración, la delegación de dominio quedó operativa de punta a punta.

Solución de problemas

Mensaje / síntoma Causa probable y solución
"unauthorized_client" al probar la conexión El error más común. El conector te dirá exactamente qué revisar: 1) que el Client ID esté agregado en el Admin Console (paso 6 de la sección anterior), 2) que los scopes coincidan carácter por carácter con los dos indicados (sin espacios extra), 3) que el buzón de prueba pertenezca al mismo dominio Workspace. Solo el superadministrador puede corregir el punto 1.
"La Gmail API no está habilitada en el proyecto de Google Cloud…" Falta habilitar la Gmail API en el proyecto (paso 2 de la sección anterior). El mensaje del conector incluye el enlace directo de activación; habilítala y espera 1-2 minutos.
"…no contiene un JSON válido" Se pegó un fragmento del archivo o se modificó el contenido. Vuelve a abrir el .json descargado y pega todo su contenido, sin editarlo.
Funciona con el buzón de prueba pero falla con otro buzón del dominio Verifica que ese otro buzón exista y esté activo en el mismo dominio Workspace — la delegación cubre todo el dominio automáticamente, pero un correo mal escrito o de otro dominio siempre fallará.
"Gmail API no respondió correctamente (HTTP 429)" Límite de cuota temporal de la API. Es transitorio; el agente puede reintentar en unos segundos.
El conector aparece "Sin configurar" tras guardar Algún campo obligatorio quedó vacío. Ábrelo de nuevo y completa el JSON de la cuenta de servicio y el buzón de prueba.

Preguntas frecuentes y notas de seguridad

¿Qué tan sensible es el JSON de la cuenta de servicio?

Es la credencial de mayor cuidado de los tres conectores Gmail. A diferencia de un refresh token de OAuth2 (que solo da acceso a un buzón), esta clave puede impersonar cualquier buzón autorizado del dominio mientras la delegación siga activa. Trátala con el mismo cuidado que la contraseña de un administrador — nunca la compartas por chat, correo o capturas de pantalla.

¿El agente puede acceder a buzones que no le he indicado?

Técnicamente la credencial lo permitiría (la delegación cubre todo el dominio), pero el agente solo actúa sobre los buzones que el usuario le menciona en la conversación — no explora ni descubre buzones por su cuenta. La restricción real depende de cómo uses el conector, no de un límite técnico de la credencial.

¿El agente puede borrar correos o cambiar la configuración del buzón?

No. El conector abre todas las conexiones limitadas a los scopes gmail.readonly y gmail.send; Gmail rechaza cualquier operación fuera de esos alcances aunque el código lo intentara.

Rotación de credenciales

Recomendado cada 90 días o según tu política: genera una nueva clave JSON en Google Cloud Console (la cuenta de servicio puede tener varias claves activas a la vez), actualízala en el formulario del conector, prueba la conexión, y luego elimina la clave anterior. La delegación de dominio no cambia — sigue asociada al mismo Client ID.

¿Qué hago si el JSON se compromete?

  1. El superadministrador elimina la entrada de delegación en el Admin Console (Seguridad → Delegación en todo el dominio) — esto revoca el acceso de inmediato a todos los buzones.
  2. Elimina la clave comprometida en Google Cloud Console (IAM y administración → Cuentas de servicio → Claves).
  3. Genera una nueva clave, vuelve a autorizar la delegación con el mismo Client ID, y actualiza el formulario del conector.
Buenas prácticas Usa una cuenta de servicio dedicada solo a este conector; autoriza únicamente los dos scopes mínimos; nunca compartas el JSON por canales no seguros; y revisa periódicamente en el Admin Console qué Client IDs tienen delegación de dominio activa en tu organización — es la superficie de mayor riesgo de todo el catálogo de conectores Gmail.
